# 010. 단지 좌표: 행안부 도로명주소 API로 지오코딩, 지도는 Leaflet + OSM

- 상태: 확정
- 날짜: 2026-10-28 (초안), 2026-10-31 (실데이터 적재 결과 반영)
- 관련: [ADR 002](002-trade-data-schema.md) (`apt_complex.location`), [ADR 003](003-upsert-with-jdbc-template.md) (단지 upsert 갱신 대상)

## 1. 배경

`apt_complex.location GEOMETRY(Point, 4326)`은 V1부터 있었지만 비어 있다 (단지 8,591개). 실거래가 API는 좌표를 주지 않고 지번(`jibun`)과 도로명(`road_address`, 예: "송파대로 345")만 준다. 4단계의 반경 검색은 PostGIS로 하므로 **좌표를 DB에 저장할 수 있어야** 한다.

2026-10-28 기준 단지 주소 상태:
- 지번은 8,591개 모두 있고, 그중 7개는 `산11-244`, `BL-3-1`, `가-238`처럼 특이한 형태다
- 도로명은 8,588개에 있고, 1개는 건물번호 없이 "만리재로"만 있다
- 도로명이 같은 단지가 있다 (서로 다른 `(sgg_cd, road_address)`가 8,475개). 임대동 등이 다른 `apt_seq`로 나뉜 경우라 좌표가 같아도 된다

## 2. 결정 근거

### ① 후보와 저장 약관

| 후보 | 저장 | 비고 |
|---|---|---|
| 카카오 로컬 API | **불가** | 응답 원본·가공 데이터 저장을 허용하지 않는다는 답변 (devtalk). 화면 표시 시점마다 실시간 호출만 허용 |
| 브이월드 지오코더 2.0 | **불가** | 가이드에 "API 요청은 실시간으로 사용하셔야 하며 별도의 저장장치나 데이터베이스에 저장할 수 없습니다" 명시. 일 4만 건 |
| 행안부 위치정보요약DB (파일) | 가능 | 신청서 작성과 이용목적 심사를 거쳐야 받는다. 신규 단지는 파일을 다시 받아야 반영된다 |
| **행안부 좌표제공 API** | 가능 | 공공데이터, 무료. 검색 API로 건물 코드를 얻은 뒤 좌표를 받으므로 단지당 2–3회 호출 |

저장이 안 되면 매 요청마다 수천 단지를 지오코딩해야 하고 PostGIS 인덱스도 쓸 수 없다. 그래서 카카오·브이월드는 제외했다. 파일 방식은 API 의존이 없지만 심사를 기다려야 하고, 매일 수집되는 신규 단지를 자동으로 반영할 수 없다. API 방식은 신규 단지를 배치에서 바로 처리할 수 있다.

### ② 주출입구 좌표를 그대로 쓴다

좌표제공 API는 건물 중심이 아니라 주출입구 좌표를 준다. 단지 규모(수백 m)에 비해 차이가 작고, 반경 검색(500m–2km)의 용도에는 충분하다. 큰 단지는 주출입구가 단지 끝에 있을 수 있다는 점은 한계로 둔다 (4. 한계). 헬리오시티는 단지 북동쪽 모서리(송파역 옆)에 찍힌다.

### ③ 법정동코드와 번호로 결과를 검증한다

검색 API는 키워드 검색이라 정확히 일치하지 않아도 비슷한 주소를 돌려준다. 그래서 두 가지를 모두 확인한다. 맞는 결과가 없으면 틀린 좌표를 저장하는 대신 MISMATCH로 남긴다. 틀린 좌표는 지도에서 눈에 띄지 않게 섞이지만, 비어 있는 좌표는 개수로 보인다.

1. **법정동**: 단지는 법정동코드(`sgg_cd` 5자리 + `umd_cd` 5자리)를 갖고 있고, 검색 결과의 `admCd`도 같은 법정동코드다. 둘이 같아야 한다
2. **번호**: 같은 동 안에서도 다른 건물이 올 수 있다. 실제로 "공릉동 270-71"을 검색하면 다른 필지인 270-47(청수대) 건물이 나와서, 대명아파트가 청수대 좌표로 저장됐다(2026-10-31 발견, 같은 좌표를 가진 단지 점검). 그래서 번호까지 같아야 쓴다
   - 도로명 검색: 결과의 도로명(`rn`)과 건물 본번·부번(`buldMnnm`·`buldSlno`)
   - 지번 검색: 결과의 번지 본번·부번(`lnbrMnnm`·`lnbrSlno`)과 산 여부(`mtYn`)
   - "BL-3-1", "가-238"처럼 숫자 번지가 아닌 지번은 번호를 맞춰 볼 수 없어서 검색하지 않는다 (NOT_FOUND)

나머지 규칙:
- 도로명으로 찾았는데 맞는 결과가 없으면 지번으로 한 번 더 찾는다
- 결과가 여러 건이면 두 조건을 모두 만족하는 첫 건을 쓴다

무작위 300개 단지로 잰 결과(번호 확인을 넣기 전, 2026-10-31): 도로명으로 찾은 296건은 모두 번호까지 같았다. 지번으로 다시 찾은 4건 중 1건(위 사례)이 다른 필지였다.

### ④ 실패는 기록하고 다시 부르지 않는다

8,591개 중 일부는 어떤 방법으로도 찾지 못한다 (특이한 지번 등). 기록하지 않으면 실행할 때마다 같은 단지에 호출을 쓴다. `geocode_attempted_at`은 **마지막 시도 시각**이다 (성공 시각이 아님). 실패한 단지는 `retryFailed=true`로만 다시 시도한다. 이때 시도 시각이 오래된 순서로 고르므로, 나눠 실행해도 같은 단지만 반복하지 않는다.

일시 오류(타임아웃, 5xx, `-999`, 빈도 제한 `E0007`)는 단지 문제가 아니므로 기록하지 않는다. 다음 실행이 자연히 다시 시도한다. 다만 **일시 오류가 5회 연속되면 서버 장애로 보고 실행을 멈춘다**. juso 서버가 내려가 있으면 `limit=1000` 요청 하나가 단지마다 타임아웃(연결 5초 + 읽기 10초)을 다 겪어야 끝나기 때문이다. 멈추면 그때까지의 결과를 `stopped=true`로 돌려준다. 중간에 다른 결과가 하나라도 있으면 연속 횟수를 다시 센다.

`E0007`("짧은 시간에 다량의 주소검색 요청이 있습니다")은 처음에 OTHER로 분류했다. 그래서 첫 전체 적재에서 1,132개 단지가 API_ERROR로 잘못 기록됐다(2026-10-30, 로컬에서 되돌림). 빈도 제한도 단지 문제가 아니므로 일시 오류로 분류를 바꿨다. 호출 간격은 ⑥에 적었다.

키 문제는 남은 호출도 모두 실패하므로 실행을 멈춘다. 설정에 키가 없으면(`MISSING_KEY`) 관리 API가 503(기능을 쓸 수 없는 상태), juso가 키를 거부하면(`E0001` 미승인, `E0014` 만료, 401·403) 502(업스트림 오류)로 응답한다. 검색·좌표 키는 승인이 따로 나므로 각 호출은 자기 키만 확인한다. 좌표 키 승인을 기다리는 동안에도 검색 API는 쓸 수 있다.

### ⑤ 주소가 바뀌면 좌표를 지운다

수집 upsert는 단지 주소를 최신 값으로 갱신하지만 좌표는 건드리지 않았다 (ADR 003). 그러면 주소가 바뀐 단지의 좌표가 옛 주소 기준으로 남는다. upsert에서 시군구·법정동·지번·도로명 중 하나라도 바뀌면 `location`, `geocode_attempted_at`, `geocode_error`를 NULL로 되돌린다. 다음 지오코딩 실행이 새 주소로 다시 받는다. 이름·건축연도만 바뀌면 그대로 둔다.

단지 주소는 더 늦은 계약일의 거래일 때만 바뀐다(2026-10-31, ADR 003). 그래서 수집 순서 때문에 주소가 옛 값과 새 값을 오가며 좌표를 반복해서 지우는 일은 없다.

반대 방향의 경쟁도 막는다. 지오코딩이 단지를 고른 뒤 좌표를 받기 전에 수집이 주소를 바꿀 수 있다. 저장할 때 고를 때의 주소와 지금 주소가 같은 경우에만 쓴다.

### ⑥ 실행: 관리 API를 나눠 호출

전체 적재는 약 1만 7천 회 호출이다 (단지당 검색 1–2회 + 좌표 1회). 요청 하나로 돌리면 HTTP 타임아웃에 걸릴 수 있어서 `limit`(기본 1000, 최대 2000)으로 나눠 호출한다. 응답의 `remaining`이 0이 될 때까지 반복한다.

```bash
curl -X POST "http://localhost:8080/api/admin/geocode?limit=1000"
```

쓰기는 단지마다 바로 커밋한다. API를 호출하는 동안 트랜잭션·커넥션을 잡지 않고, 중간에 멈춰도 처리한 단지는 남는다.

**신규 단지는 수집 배치가 채운다 (2026-10-31).** 수집 Job의 마지막 step이 좌표 없는 단지를 최대 200개(`COLLECT_GEOCODE_LIMIT`) 처리한다(`retryFailed=false`). 300ms 간격으로 약 2분이다. backfill처럼 새 단지가 한꺼번에 많이 생기면 배치가 실행마다 200개씩 따라잡고, 급하면 관리 API로 한 번에 채운다. 키가 없거나 지오코딩이 실패해도 수집 결과와 종료 코드는 바뀌지 않는다 (ADR 006 ①·⑥).

**호출 간격 300ms (추정에 따른 값)**: juso는 호출 한도를 공개하지 않는다. 그래서 측정값으로 정했다.
- 관측 (2026-10-30)
  - 100ms(초당 약 10회): 단지의 약 60%가 `E0007`. 10초마다 성공 약 19건, `E0007` 약 31건이 처음부터 끝까지 고르게 섞였다. 한도는 초당 4–5회쯤으로 **추정**한다
  - 300ms(초당 약 3.3회): 단지 200개(약 2분, 호출 약 400회)에서 `E0007` 0건
  - 300ms로 전체 적재할 때도 `E0007`은 0건이었다(3. 측정 결과)
- 빈도 제한은 분 단위로 세는 경우가 많아서 1분이 넘게 쟀다
- 운영 메모: 나중에 `E0007`이 다시 나면 코드는 그대로 두고 `JUSO_REQUEST_INTERVAL`만 올린다. 일시 오류라 기록이 남지 않으므로 다시 실행하면 이어서 처리된다

### ⑦ 지도: Leaflet + OSM 타일

키 없이 쓸 수 있어 CI·테스트에 외부 의존이 없다. 카카오맵 SDK는 앱 키와 도메인 등록이 필요하고 전역 스크립트라 테스트가 번거롭다. OSM 타일은 출처 표시가 필수이고 대량 트래픽에는 맞지 않는다. 타일 URL을 설정값으로 두어 필요하면 브이월드 배경지도 등으로 바꾼다.

**출처 표시**: 단지 좌표는 행정안전부 데이터(공공누리 제1유형, 출처표시)다. 지도의 attribution에 OSM과 함께 "주소·좌표: 행정안전부"를 넣는다.

## 3. 측정 결과 (2026-10-31, 로컬, 서울 단지 8,591개)

번호 확인 규칙(③)을 넣은 코드로 전체를 다시 적재한 결과다. 호출 간격 300ms, `limit=1000` 9회.

| 결과 | 단지 | 비율 |
|---|---|---|
| 성공 | 8,538 | 99.38% |
| NOT_FOUND | 38 | 0.44% |
| MISMATCH | 15 | 0.17% |
| NO_COORD, API_ERROR, 일시 오류(`E0007` 포함) | 0 | 0% |

- 걸린 시간: 5,208초(약 87분). 1,000개에 약 605초다
- 실패 53개는 대부분 오래된 단지다(평균 1990년 준공). 2025년 이후 거래가 있는 단지는 11개뿐이다. 재건축 등으로 juso에서 주소가 사라진 경우로 보인다
- 좌표가 없는 단지의 거래: 최근 12개월 유효 거래의 0.06%(62,427건 중 36건), 전체 기간의 0.32%
- 번호 확인 규칙의 효과: 넣기 전과 비교하면 9개가 바뀌었다
  - 7개는 성공에서 MISMATCH로 바뀌었다. 예: "○○ 47"을 검색하면 "○○1길 47"처럼 이름이 비슷한 다른 도로가 먼저 나온다
  - 2개는 다른 도로 대신 번지가 맞는 건물로 옮겨졌다(221m, 680m)

점검:
- 서울 범위 밖 좌표: 0개
- 같은 법정동 단지들의 중앙(경위도 중앙값)에서 2km를 넘는 단지: 78개, 3km를 넘는 단지: 0개(최대 2,825m)
  - 78개 중 76개는 신정동·봉천동·화곡동처럼 넓은 법정동의 가장자리에 무리 지어 있다(500m 안에 같은 동 단지가 있음)
  - 혼자 떨어진 2개(신정로 110, 구로중앙로 229)는 같은 도로 다른 단지와의 거리가 건물번호 차이와 맞았다. 건물번호 1은 약 10m다
- 같은 좌표를 가진 단지: 86그룹, 200개
  - 85그룹은 도로명주소까지 같다(임대동 분리 등)
  - 도로명이 다른 1그룹은 재건축 사례다. 코오롱상가아파트(1988년, 마지막 거래 2021-10)와 같은 자리의 더샵강동센트럴시티(2025년)
- 지도 확인: 헬리오시티(송파대로 345 주출입구, 송파역 옆)와 무작위 2개 단지를 OSM에서 눈으로 확인했다

## 4. 한계

- 좌표는 주출입구 기준이다. 큰 단지는 단지 중심과 수백 m 차이가 날 수 있다
- 도로명주소 API의 호출 한도는 공개되지 않았다. 빈도 제한은 `E0007`로 오고, 300ms 간격은 측정에 따른 **추정**일 뿐이다. 한도가 바뀌면 `E0007`이 다시 날 수 있다(⑥의 운영 메모)
- 공식 개발 가이드 페이지를 외부에서 열 수 없었다. 응답 구조와 필드는 실제 응답으로 확인했다(검색 2026-10-28, 좌표 2026-10-30, `src/test/resources/sample/juso-*.json`)
- 번호 확인으로 다른 건물을 고르는 일은 막지만, juso에 아예 없는 주소(재건축 등)는 찾지 못하고 MISMATCH나 NOT_FOUND로 남는다

## 5. 재검토 조건

- 실패율이 높으면 (예: 1% 이상) 실패 유형을 보고 검색어 규칙이나 출처를 다시 본다
- 서울 밖으로 지역을 넓히면 시도명 처리와 호출량을 다시 본다
- 지도 트래픽이 늘면 OSM 타일 대신 자체 타일 서버나 상용 타일을 쓴다
