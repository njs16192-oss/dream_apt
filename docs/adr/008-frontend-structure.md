# 008. 프론트엔드 구성: 생성 타입 + openapi-fetch, 기간은 전체를 받아 화면에서 자른다

- 상태: 확정
- 날짜: 2026-10-26
- 관련: [ADR 001](001-tech-stack.md) (React + Vite), [ADR 007](007-view-criteria.md) (조회 기준, 집계 중 표시, 조회 기간 제한)

## 1. 배경

3단계 조회 API(ADR 007)를 화면으로 보여준다. 백엔드와 프론트엔드를 한 사람이 같이 바꾸므로, 응답이 바뀌었을 때 화면이 조용히 깨지지 않게 하는 구조가 가장 중요하다. 차트는 ADR 007의 "집계 중" 규칙과 빈 달을 화면에서 같은 방식으로 보여줘야 한다.

## 2. 결정 근거

### ① API 타입: 생성 파일 커밋 + `openapi-fetch`

- **생성 원본은 `public` 그룹 문서**(`/v3/api-docs/public`)다. 관리 API(`/api/admin/**`)는 화면에서 쓰지 않으므로 타입에 넣지 않는다
- **생성 파일을 커밋한다.** 빌드·테스트·CI가 백엔드를 띄우지 않아도 되고, 백엔드 변경이 PR diff에 타입 변경으로 드러난다
- **`openapi-fetch`를 쓴다.** `fetch`에 응답 타입만 붙이면 경로 오타나 파라미터 이름 변경은 못 잡는다. `openapi-fetch`는 `api.GET('/api/complexes', { params: { query: { q } } })`의 경로·파라미터까지 생성 타입으로 검사한다
  - 확인: 스펙에서 `q`를 `keyword`로, `/api/regions`를 `/api/sgg`로 바꿔 생성하면 `tsc`가 해당 호출을 오류로 잡았다
- **`--properties-required-by-default`**: 백엔드 스펙에 `required`가 없어서 그대로 생성하면 모든 필드가 선택값(`?`)이 된다. 이 옵션은 모든 필드를 필수로 본다. nullable 필드는 스펙에 `["integer", "null"]`로 표시되어 있어 `number | null`로 정확히 나온다
  - **전제: 백엔드가 null 필드도 응답에 싣는다.** 지금은 Jackson `NON_NULL` 설정이 없어서 `"lastDealAmount": null`처럼 항상 실린다. **나중에 `NON_NULL`을 켜면 필드가 빠질 수 있어 이 전제가 깨진다.** 그때는 이 옵션을 빼고 백엔드에서 `requiredMode`를 명시해야 한다
- **TS 6 peer 충돌**: `openapi-typescript` 7.13은 peer가 `typescript ^5.x`다. 생성 결과는 TS 6에서 문제없어서 `package.json`의 `overrides`로 이 패키지에만 프로젝트의 TypeScript를 쓰게 했다. `npx openapi-typescript@버전`은 devDependency로 고정되지 않아 재현성이 떨어지고, `legacy-peer-deps`는 모든 패키지에 적용되어 다른 충돌까지 가리므로 쓰지 않는다

### ② 조회 기간: 전체를 받아 화면에서 자른다

- 단지 면적별 월별 가격 API는 기간 제한이 없고 응답이 작다 (전체 기간 82개월, HTTP 포함 9ms, ADR 007 ③)
- 구 월별 거래량 API는 최대 120개월인데, 데이터가 2020-01부터라 지금 전체가 약 82개월로 그 안에 들어간다. "전체"는 `from = 기준월 − 119개월`로 요청한다
- 그래서 두 차트 모두 기간 선택(1년/3년/5년/전체)을 바꿔도 다시 요청하지 않는다. 캐시도 화면당 하나로 단순하다

### ③ 시계열 표시

- **집계 중 달**: 선 하나의 일부 구간만 점선으로 그릴 수 없어서 확정 구간(실선)과 집계 중 구간(점선) 두 선으로 나눈다. 두 선은 경계 달(마지막 확정 달) 한 점을 같이 가져서 이어 보인다
  - 마지막 확정 달이 빈 달(null)이면 공유할 점이 없어 두 선이 떨어진다. 빈 달에서 선을 끊는 규칙과 같은 결과이므로 그대로 둔다
  - 경계 달은 두 선에 모두 들어 있으므로 툴팁은 월 기준 커스텀 툴팁으로 한 번만 보여준다
- **빈 달**: 거래가 없는 달은 응답에 없다. 화면에서 `null`로 채우고 선을 잇지 않는다(`connectNulls={false}`). 잇게 하면 거래가 없던 기간에 가격이 서서히 움직인 것처럼 보인다
  - 채우는 범위: 시작은 1년/3년/5년이면 그 기간의 첫 달, 전체면 **첫 데이터 달**(응답의 `from`이 null이거나 데이터보다 이르므로). 끝은 **`baseDate`가 속한 달**

### ④ 표기

- 금액은 API가 만원 정수로 준다(ADR 002). "24억 5,000만"처럼 억과 만원으로 나눠 쓰고, 0인 부분은 생략한다 ("1억", "9,999만")
- 평은 **전용면적 기준**이다 (1평 = 400/121㎡). 흔히 쓰는 "34평형"은 공급면적 기준이라 같은 집이 25.7평으로 보인다. API에 공급면적이 없으므로 숫자 앞에 '전용'을 붙여 헷갈리지 않게 한다

## 3. 한계

- 생성 타입은 응답의 **모양**만 보장한다. 값의 의미(단위, 일괄 거래 포함 여부)가 바뀌면 컴파일 오류가 나지 않는다
- `schema.d.ts`를 다시 생성하지 않고 백엔드만 바꾸면 화면은 옛 타입으로 컴파일된다. 지금은 사람이 지키는 규칙이고, CI가 생기면 백엔드를 띄워 생성한 결과와 커밋된 파일을 비교하는 검사를 넣는다
- `NON_NULL` 전제 (① 참고)

## 4. 재검토 조건

- 구 거래량 전체 기간이 120개월을 넘을 때 (데이터가 2020-01부터면 2029-12 이후). 서버 제한을 올리거나, 그 구간만 기간별로 요청한다
- 백엔드에 `NON_NULL`을 켤 때
- 수집 지역이 넓어져 응답이 커질 때 (전체 받기 비용 재측정)
